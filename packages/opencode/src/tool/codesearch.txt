Find real-world code by searching for literal substrings in source files. Multiple words match lines containing all of them — no operators, quotes, or booleans needed. For flexible patterns, use regex with useRegexp=true.

Translate questions into code-search queries:
- "How to handle CORS in FastAPI?" → 'CORSMiddleware' with language=['Python']
- "What does a React fetch pattern look like?" → 'await fetch(' with language=['TypeScript']
- "Show me Flask error handler patterns" → '@app.errorhandler' with language=['Python']
- "How do projects import NextAuth?" → 'import.*NextAuth' with language=['TypeScript', 'TSX'] and useRegexp=true

Multiple words like "fastapi fetch react" match lines containing all three. Do not wrap terms in quotes, AND, or OR — they become literal characters.

Available parameters: query (required), language (TitleCase array), repo, path, matchCase, matchWholeWords, useRegexp. No other parameters are supported.

Rules — follow these strictly:
1. First search: query only, no filters. Add language/repo/path only to narrow after seeing what's available.
2. grep.app searches for literal substrings. Spaces match lines with ALL words. Quotes and operators become literal characters. Use regex with useRegexp=true for flexible matching: 'fastapi|flask|django' matches any of the three.
3. Language values use TitleCase: ['TypeScript'], ['Python'], ['JavaScript']. Lowercase will not match.
4. Never invent repo names. Only filter by repo if you saw that repo in a previous search result.
5. Stay on the user's question. Don't chase internal constants or implementation details from unrelated repos.
